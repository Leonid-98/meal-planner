# Меню — планировщик еды

Личное приложение на двоих: рецепты с КБЖУ из ингредиентов, план на неделю
(в том числе «приготовить один раз, доесть завтра»), список покупок на выбранный
период. Не трекер калорий: цифры на порцию нужны как справка для внешнего приложения.

Стек и деплой — как у `budget-app`: Flask + SQLite + HTMX, образ на GHCR,
вход через oauth2-proxy перед Caddy. Приложение само пользователей не
аутентифицирует — доверяет заголовку прокси.

## Запуск локально

Через venv:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
MOCK_AUTH_EMAIL=user1@example.com .venv/bin/flask --app wsgi run --port 8000
```

Через Docker (то же, что и у budget-app; данные в `./data-local`):

```sh
docker compose up --build
```

Открыть <http://127.0.0.1:8000>. База создаётся сама (`instance/food.db` или
`/data/food.db` в контейнере) и наполняется библиотекой из ~70 базовых
продуктов с приблизительными КБЖУ на 100 г — проверяйте по упаковке и правьте.

Несколько пробных рецептов, чтобы было с чем играть:

```sh
MOCK_AUTH_EMAIL=user1@example.com .venv/bin/flask --app wsgi seed-demo
```

Тесты: `.venv/bin/pytest -q`.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DATABASE_PATH` | `instance/food.db` | файл SQLite |
| `IDENTITY_HEADER` | `X-Forwarded-Email` | заголовок с почтой от прокси (в проде `X-Auth-Request-Email`) |
| `MOCK_AUTH_EMAIL` | пусто | подставить почту без прокси (локально) |
| `FOOD_USER1_EMAIL` / `FOOD_USER1_NAME` | `user1@example.com` / `Лёня` | первый пользователь |
| `FOOD_USER2_EMAIL` / `FOOD_USER2_NAME` | `user2@example.com` / `Аня` | второй пользователь |

## Структура

- `app/models.py` — таблицы: пользователи, ингредиенты, рецепты и их строки,
  теги, записи плана (`meal_entries`, остатки через `leftover_of_id`), порции
  по людям, отметки списка покупок, свои строки, настройки.
- `app/services.py` — расчёт граммов и КБЖУ, календарь, сборка списка покупок,
  «Заполнить неделю».
- `app/routes.py` — все маршруты; формы обычные, HTMX подменяет страницу.
- `app/templates/` — один базовый шаблон и по странице на раздел.
- `design/` — макет (исходники экранов и скрипт сборки).

Схема создаётся `db.create_all()`; миграции (Alembic) появятся перед первым
деплоем в прод, когда данные станут ценными.
